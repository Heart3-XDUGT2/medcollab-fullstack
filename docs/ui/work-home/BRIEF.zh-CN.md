## 本轮要解决的问题

上一轮只完成资料呈现与显示偏好，不能代表完整首页。本轮让用户能从工作首页继续寻找资料，管理常用收藏与最近记录，查看有真实依据的 CT 帧覆盖率；仍保留完整资料库及原有业务能力。

用户批准的功能目标，不是排版施工图：

- 工作首页与完整资料库可切换，可选择本人默认入口；切换不丢搜索、排序、选择和原显示偏好。
- 工作首页有继续入口、收藏、最近和团队入口；少资料与空内容仍可使用，不做公司工单或营销仪表墙。
- 演示空间支持收藏/取消、最近记录移除/清空等完整交互；只在内存，刷新/退出即丢弃，示例来源明确。
- 真实账号尚无收藏/最近 API。不能自作主张请求需求草案中的路径、写入浏览器医学历史来冒充云同步，或将尚未成功打开的工作台记为已打开。
- 继续工作首版返回数据集，复用受控工作台启动链。没有真实序列恢复或本地草稿状态时，不声称恢复精确位置或同步了草稿。
- 数据集呈现真实统计支持：使用已有 `/api/datasets/{datasetId}/annotation-stats`，不下载完整 Labelmap 来算首页数字。
- 区分服务器已接受的共享画布 `progress` 和已归档 `publishedProgress`。非空掩码 CT 帧/支持的 CT 总帧是覆盖率，不是医学质量、器官完整度或审核通过率。
- 首页模块显隐/顺序与默认入口属于显示配置，本机按账号隔离；不以云偏好 API 为前置条件。原 v1 显示偏好必须保留或明确兼容，不能无声覆盖已有清单选择。
- 资料就绪状态、协作变化提醒、保存复杂筛选、精确序列恢复列为后续，不在本期虚构这些能力。

具体构图、组件、信息层级、交互细节由执行官自主设计。保持既有 MedCollab 视觉体系，扩展真实工作能力，不重新做品牌。

## 技术与事实边界

1. 本轮只动 Portal、对应测试与交接记录。不动 Java、网关、OHIF、实际数据库和运行配置，不重启旧服务，不启用历史 SEG 清理。
2. 保留 Cookie、动态 CSRF、身份与取消边界、未知写入保护、1 GiB 上传，以及已合并的所有本地修复。
3. 统计只读请求遵守相同账号生命周期。退出/换账号/切模式/失权后，旧结果不能复现。重复资料区块应复用一次统计，不对全列表无界发请求或持续轮询。
4. 当前运行后端可能仍旧版。须检查实际统计能力，不能把“旧版本没有统计路由”的 404 当成数据集被删除；缺能力时保留资料库与登录功能。
5. 0 帧、无发布、未归档、加载、旧值、接口缺能力、401、404、423、服务失败分别处理。错误不归零，空集合不算 100%，舍入不把不足全部的比例写成全部覆盖。
6. 演示状态与真实业务完全隔离。演示统计自洽、可复核，不由 `instanceCount` 冒充 CT 总帧，不生成真实患者影像或虚假账号。
7. 首页设置仅保存白名单显示值，不保存资料名/对象 ID/医学内容/凭证/运行目的地。个人偏好不能改变队友或数据权限。
