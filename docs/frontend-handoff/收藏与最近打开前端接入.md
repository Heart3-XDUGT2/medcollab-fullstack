## 用户操作

- 完整资料库：卡片星标或更多操作中的“收藏到首页”；工作首页显示真实收藏并允许取消。
- 最近打开：OHIF 成功加载所选 CT、目标视口已有真实像素后自动上报。Portal 点击按钮、只读元数据、加载失败、独立演示不创建真实历史。
- 工作首页支持移除一条记录、清空记录、加载更多；“继续工作”在没有手动选择时使用最近打开的数据集。只重开资料，不恢复视角、切片或本机草稿。
- 切回页面会重新读取当前账号列表。清理记录不会删除 CT、SEG、收藏或 IndexedDB 草稿。

## 必须保留的兼容性

1. 业务 datasetId 不等于 DICOM UID。所有影像继续走 Java 授权后的 DICOMweb，前端不直连裸 Orthanc。
2. HTTP 成功仍为 200 JSON；所有新列表 total 是过滤当前权限后的分页前总数。收藏条目为 { dataset, favoritedAt }，最近条目为 { dataset, lastOpenedAt }。
3. 写入前比较 issuer + subject，再使用同次 /api/session 返回的 csrfHeaderName/token；切账号、登出、进入演示、卸载必须取消旧上下文。取消不能撤回服务器已完成的写入。
4. 收藏状态通过批量接口读取，不能因首页只加载前 20 条，就把其余资料误判为未收藏。
5. 工作台 recent POST 的 eventId 在同次打开中固定，generation 必须取本次打开前的 context。历史已清理或上下文过期返回 409 时不得取新 context 重播旧打开；网络失败也不自动重写。
6. 浏览器原生 fetch 需作为普通函数调用；不要用 reporter.fetcher(...) 给它绑定业务对象。上报失败不能阻止 CT 显示或绘制。
7. 团队摘要使用 teamId/teamName；点击其详情进入对应团队库，打开影像仍传业务 datasetId，不套用个人重命名/共享操作。
8. 工作台关闭或重新绑定仍需重置 stats/statsLoading/statsError/statsUpdatedAt，防止上个数据集的进度残留。
