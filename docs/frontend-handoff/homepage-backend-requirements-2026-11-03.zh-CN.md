# 首页功能与后端支持需求

日期：2026-11-03。面向：后端队友、OHIF 工作台队友、Portal 前端。

状态：**需求交接草案，不是已实现接口协议。本文只新增文档，没有改程序、数据库、OpenAPI、运行配置或部署。**

初次核对范围：本地 `medcollab-fullstack`，HEAD 为 `fb2ce39`，包括当时未提交改动。

**同日远端更新校正：已取得主分支 `5cf877c`，新增统计接口已在源码中实现。首页应优先调用 `GET /api/datasets/{datasetId}/annotation-stats`，不要再把轻量统计列为后端尚未建设的能力，也不要默认下载完整 Labelmap 来计算。** 配套还有个人历史统计和序列统计，完整字段及语义见 [标注统计接口](标注统计接口.md)。这仍不代表当前运行服务已升级；本轮没有重启、迁移实际数据库或启用清理任务。

## 1. 结论先行

首页欠缺的不全是后端功能。前端此前只完成了资料呈现和显示偏好，遗漏了收藏、最近打开、继续工作和首页内容组织等产品能力。

本次准备补齐的功能分为三类：

1. **确实需要新增后端支持**：云端个人收藏、最近打开的保存/读取/清理，以及这些记录的个人和团队资料授权过滤。
2. **已有后端实现，待前端接入**：按用户提出的公式计算 CT 帧标注覆盖率；新版直接提供数据集/序列统计，不必先建设任务分配、审核或手动完成系统，也不必由首页逐份下载掩码。
3. **可以直接由前端完成**：首页模块显隐/顺序、默认入口、现有个人/团队入口整合、局部错误与空态。只有要求跨设备保存这些显示设置时，才需要账号偏好接口。

“后端暂时没有”不等于取消功能；“调研提到过”也不等于把所有竞品功能全部列为本期必须开发。

## 2. 本期功能与依赖清单

P0：本期产品功能；P1：配套优化或后续能力。优先级不是约定工期。

| 功能 | 用户得到的效果 | 当前能力与缺口 | 本期安排 |
| --- | --- | --- | --- |
| 我收藏的 | 收藏常用数据集，随时取消收藏，换电脑仍能找到 | 未发现个人收藏的接口或存储；需新增 | P0，后端 + 前端 |
| 最近打开 | 按本人真正打开资料的时间找回个人/团队数据集，可移除或清空记录 | 没有打开历史；创建时间不能代替 | P0，后端 + 工作台 + 前端 |
| 继续工作 | 从最近资料返回工作台，不用重新找库 | 数据集启动已有支持；准确记录成功打开需工作台回执 | P0，先做到返回数据集，不承诺精确恢复视角/草稿 |

| 最近发布/最近更新 | 辨别队友最近发布过标注的资料 | 发布记录已有时间；数据集级聚合、通用修改事件未提供 | P1；优先复用发布记录，不虚构活动流 |

| 固定置顶顺序、保存筛选视图 | 常用资料排序、复用重复查询 | 可先做个人本机设置；跨设备需额外保存能力 | 后续，不和基础收藏捆绑 |

本期不要求新建企业工单、任务分派、审核角色、模型训练、任意拖拽首页编辑器、存储配额或在线人数系统。

## 3. 已有后端：哪些不要重复建设

源码核对见文末。以下属于本地实现事实，不是本次新 API 承诺：

- `/api/session`、Cookie 会话、动态 CSRF、登录/注册导航已有。
- `GET /api/datasets` 提供当前账号的个人/共享/公共资料；它**不含团队资料库**。
- `GET /api/teams`、`GET /api/teams/{id}/datasets` 已提供团队入口与独立资料库。
- `DatasetItem` 只有 `id/name/access/ownerUsername/instanceCount/createdAt`，没有收藏、访问时间或进度。
- `/api/datasets/{datasetId}/workspace` 已提供工作台启动上下文；拿到上下文不等于影像实际打开成功。
- `/segmentation/sources`、各序列的 `/labelmap`、`/status`、发布接口已有。发布记录按数据集和序列区分。
- 新版提供 `/api/me/annotation-stats`、`/api/datasets/{datasetId}/annotation-stats`、`/api/datasets/{datasetId}/segmentations/{seriesId}/stats`。个人历史有效修改次数不等于精确落笔次数，也不能反推当前数据集完成度。
- 工作草稿目前主要在浏览器 IndexedDB；服务器旧草稿接口已停用写入。首页不能据此宣称云端草稿同步。
- 单实例 PNG preview 已有，不能把“数据集缩略图组织尚缺”写成“后端完全没有预览”。

保持个人共享不可撤销、团队库独立授权的现有规则；收藏和最近入口不能扩大资料权限。

## 4. 必须新增：个人收藏与最近打开

### 4.1 共同的资料摘要

收藏和最近都需要返回可直接辨认的授权资料摘要，而不是只返回一串无法解析的 ID。

最小信息：

- 业务 `datasetId`、当前名称、创建者显示名、实例数和创建时间。
- 明确 `scope=personal|team`；团队资料返回 `teamId/teamName`，个人资料保留真实 owner/shared/public 关系。
- `isFavorite`；最近列表另有 `lastOpenedAt`，收藏列表另有 `favoritedAt`。
- 摘要不足以授予访问权。点击后仍由现有工作台链路重新鉴权，不接受客户端自造权限或任意跳转地址。

可以采用公共摘要模型，也可以返回兼容现有类型的结构。具体 JSON 字段和路由由后端与前端确认，不能让个人资料列表偷偷混入缺少来源的团队项。

### 4.2 收藏

需要支持：

1. 收藏本人当前有权访问的数据集，包括个人、被共享、公共及团队资料。
2. 取消本人收藏；列出本人收藏；资料列表可批量获得是否已收藏，避免每行单独查询。
3. 收藏属于本人，不修改资料、不复制文件、不通知全团队，也不要求资料编辑权限。
4. 以会话里的 `issuer + subject + datasetId` 唯一识别关系；不按用户名关联，不接受请求体指定操作者身份。
5. 重复收藏/取消不制造重复项。刷新或再次登录后状态仍在。
6. 失去权限、退出团队、资料删除后，在读取列表、总量和摘要时立即过滤。不能泄露旧名称、所属团队或影像。

建议：权限恢复后，仍保留的本人收藏关系可以重新显示；这不恢复任何访问权。后端确认是否采用此规则，并明确清理策略。

### 4.3 最近打开

需要支持：

1. 记录、读取、移除单条和清空本人的打开记录；不把它做成所有人可看的访问排行榜。
2. **成功打开的口径**：工作台确认数据集上下文与至少一个目标影像可用后，上报一次。仅点击按钮、在首页展开详情、预取列表或加载失败，不算打开成功。
3. OHIF 直接链接进入也能上报。Portal 点击跳转不提前假记成功；不能只依赖首页点击事件。
4. 每个本人/数据集保留最近一次成功打开时间，按服务器时间倒序；多次打开同一资料不堆多行。
5. 服务端给时间并核对资源访问权；不接受客户端伪造 `openedAt` 或操作者。可带非敏感 `eventId` 去重，避免重复回执改写顺序。
6. 默认只需返回数据集级入口；若要恢复到序列，可另存经服务端验证属于该集的序列引用。不在历史里保存掩码、患者名、窗口截图或任意 URL。
7. 清理历史不删除资料、收藏、发布或本地草稿。账号切换、迟到上报和清空后的旧重试不能让已清理历史意外复现。

建议首版最多保留 100 个不同数据集、90 天记录；**这是待后端确认的保留策略，不是现有能力或已批准政策**。不回填过去没有记录的访问时间。

### 4.4 路由建议，不是现有接口

| 建议方法和路径 | 目的 |
| --- | --- |
| `GET /api/me/favorite-datasets` | 本人有权访问的收藏摘要 |
| `PUT /api/me/favorite-datasets/{datasetId}` | 收藏，幂等 |
| `DELETE /api/me/favorite-datasets/{datasetId}` | 取消本人收藏，幂等 |
| `GET /api/me/recent-datasets` | 本人有权访问的最近打开摘要 |
| `POST /api/me/recent-datasets/{datasetId}` | 工作台成功打开回执，建议包含事件去重编号 |
| `DELETE /api/me/recent-datasets/{datasetId}` | 从本人最近中移除 |
| `DELETE /api/me/recent-datasets` | 清空本人最近 |

以上新增操作建议沿用当前 Portal 的 200 JSON 成功约定。是否采用这些名字由后端确认；**不要让前端现在调用这些尚不存在的路径**。

列表先授权再排序、分页、计数。分页应有稳定次序（时间加业务 ID 作为并列规则）。如果采用新分页结构，单独约定 `nextCursor/hasMore` 等字段，不改变旧接口 `total === items.length` 的含义。

## 5. CT 帧标注覆盖率：采用轻量口径

### 5.1 按用户建议定义第一版

以下默认描述已归档口径。新版同时提供 `progress`（服务器已接受的当前共享画布）与 `publishedProgress`（已登记成功的 SEG），前端可分别展示，但不得混用。个人本机尚未同步的草稿不属于其中任一值。

```text
CT 帧标注覆盖率 =
  当前有效发布标注中，至少有一个非零掩码像素的 CT 帧数
  ÷ 数据集内纳入统计的 CT 总帧数
```

例如：300 帧中有 60 帧有已发布标注，显示“已标注 60 / 300 帧，覆盖率 20%”。

它可作为首页的标注进度指示，**但不是“全部应标内容已完成”或“审核通过率”**。用户检查过的阴性帧可能没有掩码；一帧仅画一小块也进入分子。页面应把帧数和统计口径显示清楚，不单独用“完成 100%”断言工作质量。

第一版不要求为了这个指标新增任务分配、完成确认、审核流程。将来若要统计“已检查/已验收帧数”，才需要独立记录，不能从当前掩码反推。

### 5.2 当前应接入的统计接口

优先读取数据集 `/annotation-stats`；只关心当前序列时读该序列 `/stats`：

- `progress` / `publishedProgress` 都包含 `totalSlices/annotatedSlices/unannotatedSlices/ratio/percent`。`ratio` 为 0–1，`percent` 为 0–100，后者不再乘 100。
- `pendingArchive` 为 true 表示共享修改尚有未归档部分；不能将当前画布统计写成已落盘成品。
- 无可统计 CT 时，现有 API 返回 0 张、0%；前端按 `totalSlices===0` 显示暂无可统计 CT，不把空集合视为全部完成。
- 401 处理身份，404 处理失权，423 低频重读或让用户重试，5xx 保持错误状态；这些都不是“0%”。
- 合计按切片数加权；各序列内部快照一致，多序列不是冻结的同一瞬间。
- 正常读取使用已有掩码 JSON/计数缓存；旧 SEG 首次补计数可能解码，后续不应反复全量下载。

#### 旧版取数推导，仅保留作对照

下列方法说明为什么原始数据足够推导该指标，**不再作为新版首页的默认接入方案**：

1. `GET /api/datasets/{datasetId}/segmentation/sources` 返回可处理的 CT 源图像，包含 `id`、`seriesId` 等。
2. 对其中不同序列，读取 `GET /api/datasets/{datasetId}/segmentations/{seriesId}/labelmap`。
3. 对当前发布版本 `data.masks` 中非空、有效的掩码，以源帧 ID 去重，再与该数据集源帧集合取交集。
4. 分子是这一去重集合的大小；分母是目标 CT 源帧集合的大小。跨序列合并计数，不能简单平均各序列百分比。

**因此：在当前支持的单帧 CT、已发布 SEG 范围内，原则上不改后端也能先计算。** 这是源码可行性分析，本次没有加载真实资料进行性能或数值联调。

`/status` 只有发布版本、时间等，没有逐帧掩码；只有 `publishedVersion > 0` 不能推导整个序列已标完。

### 5.3 统计必须守住的边界

| 情况 | 处理 |
| --- | --- |
| 同一帧多个标签、多人发布或多个历史版本 | 只统计该序列当前发布版本，一帧最多计一次 |
| 已发布掩码被清空或改少 | 以最新有效版本重算，覆盖率允许下降，不累计历史涂过的帧 |
| 有源 CT、没有任何发布 | 已标注为 0；不能把读取失败也当成无发布 |
| 浏览器有未发布草稿 | 不计入共享覆盖率；不能让队友首页看到一个尚未上传的进度 |
| 追加导入 CT | 分母可能增加；新帧未标时覆盖率自然下降，不保持旧的假 100% |
| 重复导入同一关联实例 | 按当前数据集源帧去重，不增加分母 |
| 没有可统计 CT 帧 | 比率为 `null`，显示暂无可统计 CT；不算 0/0=100% |
| 有任一序列读取失败或尚在加载 | 显示加载/不可用/明确的部分结果，不能把部分分子除以全量分母当最终值 |
| 数据集含 MR、SEG、SR 等其他对象 | 不用 `instanceCount` 当 CT 分母；说明此指标仅覆盖 CT |
| 多帧/增强 CT 或超出当前绘制器限制 | 不把被过滤/无法处理的帧当作不存在；返回不支持/统计不完整，不能冒充全 CT 覆盖率 |
| 其他标注类型或外部导入 SEG | 没进入当前已发布 SEG 链路的结果，不假定已被统计；新增标注通道需另约定计算依据 |

特别注意：当前 `DicomSegCodec.sources()` 只接受特定单帧 CT 存储类型，并有数量等安全上限；它不是任意 DICOM 的全帧枚举器。如果无法证明完整统计范围，就不能把其子集比例标作整套资料的完整完成度。

### 5.4 轻量汇总已实现，后续关注请求规模

本节原先提出的轻量统计建议已由远端 `5cf877c` 落实，**不是本轮仍待后端实现的缺口**。以下保留成本分析与旧字段设想作为背景；实际接入严格使用当前统计契约，而不是照抄本节自拟结构。

前端能算，不代表首页应该逐个读取所有序列的完整 Labelmap。

当前 `/labelmap` 链路可能读取 Orthanc 中的 SEG、调用编解码并返回掩码。几十个数据集同时显示首页进度，会产生大量请求和掩码传输，后端也可能反复解码。不能为了首页的一个数字重复加载整份标注。

原先建议后端提供小体积覆盖率摘要；新版已有按数据集/序列的统计、发布时缓存和旧版本按需补计数。后续若首页同时显示大量数据集，可再评估批量接口及限并发，不能把“没有批量”误写成“完全没有统计”。实现上应继续满足：

- 在有效发布时复用已校验的源帧和掩码，记录该版本的有标注帧集合或计数。
- 维护源 CT 帧统计；追加导入、源集合变化、发布变化时更新或失效。
- 对旧发布做按需回填或后台计算；没有完成计算时返回 `calculating/unavailable`，不填 0。
- 读摘要仍逐项校验数据集/团队访问权；不把缓存当授权依据。
- 发布覆盖与导入并发时使用一致的版本/源范围，避免分子来自新版、分母来自不相容旧版。

这不是新的工作流系统，只是**现有源帧和标注的派生汇总**。已有单集接口即可开始接入；批量优化按实际数据量决定。

建议响应字段示例，**非现有 API**：

```json
{
  "datasetId": "EXAMPLE_DATASET_ID",
  "coverage": {
    "status": "ready",
    "basis": "published_seg_nonempty_frames",
    "scope": "single_frame_ct",
    "totalFrames": 300,
    "annotatedFrames": 60,
    "ratio": 0.2,
    "asOf": "2026-11-03T08:00:00Z"
  }
}
```

补充约束：

- `ready` 必须代表已确认声明范围内的完整数据；不能隐藏未知源帧或缺失序列。
- `ratio` 为 0–1 的比例；分母为 0 或统计不可用时为 `null`。未全部覆盖时不要因显示取整误报 100%。
- 需要区分 `calculating/unsupported/unavailable/error`；若展示旧摘要，标明已过期或更新时间，不当最新结果。
- 可返回数据范围版本、发布版本摘要、`lastAnnotationPublishedAt`，便于缓存失效和解释。
- 建议通过新批量摘要路径或兼容的可选字段提供，不破坏已有 Dataset 必填结构。最终路径和 JSON 由双方确认。

若暂不优化，前端只对可见资料限并发、按需读取，并在资料/会话/权限变化后使缓存失效；不能在没有容量验证时直接全量扇出。具体资源上限与响应时间由实际数据联调决定，本文不编造性能 SLA。

## 6. 首页设置、聚合与后续能力

### 6.1 无须新增后端就应补的部分

- 最近、收藏、资料库和团队入口的组织及模块显隐/顺序；其中业务内容等待对应 API，显示配置本身不必等待。
- 默认进入概览、最近或资料库；不改变数据权限。
- 各模块独立的加载/错误/空态、重试读取；收藏失败不能让整个资料库消失。
- 当前搜索、排序、选择在模式切换时保持；新增模块不会成为平行的一套业务数据。
- 现有来源关系、创建时间、实例数、团队身份继续复用，不用假指标填空。

本机显示偏好仍只保存白名单选项，不混存患者资料、访问历史或业务 ID。最近与收藏是独立业务记录，不塞进显示设置的 localStorage。

### 6.2 仅在需要跨设备时新增偏好接口

建议账号偏好读取/保存接口支持：版本、默认入口、模块显隐与次序，以及现有呈现/密度/字段选项。

保存只影响本人；服务器从会话取身份；校验枚举、结构和大小。并发修改需有版本冲突策略，恢复默认不能删除收藏、历史、资料或团队。老的本机偏好是否一次性迁移，要明确征得用户操作，不擅自覆盖云端设置。

### 6.3 规模化聚合和其他候选

- 首页统一概览接口可以减少请求，但不是强制采用的架构；收藏、最近、覆盖率和团队数据也可由前端并行组合。不能把“先造一个万能首页接口”当所有工作的前提。
- 全局搜索/排序若涵盖团队、收藏、历史和覆盖率，应服务端过滤授权后再分页，不能前端截取一页后冒称全库搜索。
- “最近标注发布”可聚合现有发布记录；“最近修改”若包含重命名/导入等，需额外事件或更新时间定义。两者不能混用。
- 真正的“我上传过”需要导入操作者记录。当前 owner/创建者不等于所有实例的上传者；没有记录时沿用“我创建的”。
- 缩略图可复用受控 preview，但要约定代表帧、大小、去敏/烧录文字风险、权限和缓存；不能为封面下载整套体数据。
- 保存筛选视图保存的是条件；收藏保存的是对象关系；两者分开。评论、通知、在线协作、审核、训练导出不在本期首页缺口清单内。

## 7. 共同安全与兼容要求

1. 复用 Cookie 会话和动态 CSRF；写入前重新核对身份，服务端每次验证身份及资源权限，不信客户端 user/team/access。
2. 收藏/最近/覆盖率只含当前仍可见资源；权限过滤先于计数和分页。多账号、跨 issuer、退出团队、删除资料分别验证。
3. 退出、切换账号、失权后清理当前页面的资源摘要与缓存；取消请求不能保证服务端撤销已提交操作。
4. 网络中断的写操作先读回核对，不盲目重试。可幂等的收藏、访问事件也要约定去重和迟到规则。
5. 不在 URL、日志、公开缓存或显示偏好里写患者名、掩码、凭证、邀请码。业务摘要响应使用受控的会话缓存策略。
6. 不修改现有 `/api/datasets` 返回含义、已有 1 GiB 上传、个人共享不可撤销、团队独立授权及工作台发布冲突保护。
7. 新接口未实现/不可用时前端显示真实状态；演示内容不得混入真实收藏、历史或统计。

## 8. 分工与交接顺序

| 角色 | 交付 |
| --- | --- |
| 后端队友 | P0 收藏与最近的存储/授权/API；确认摘要结构、时间与保留规则；提供现有统计 API 的部署版本与联调条件 |
| OHIF 工作台队友 | 在成功打开后发送一次回执，覆盖直接链接进入；明确已发布标注数据的口径；不因首页统计改写草稿/发布逻辑 |
| Portal 前端 | 收藏/最近/继续入口、内容设置、CT 帧覆盖率及真实错误态；先复用已有接口，不把本机配置冒充云同步 |
| 计划/审查官 | 对齐字段和范围、检查无数据泄露/假进度、组织联调与回归，不替执行官规定页面构图 |

建议顺序：先确认本文件口径和已有接口适用范围；并行做收藏/最近 API 与前端模块，接入已有统计；用当前共享和归档数据验证覆盖率算例；根据真实数据量评估批量优化；最后做三端联调。无需等一个完整任务管理系统。

## 9. 验收清单

- A 收藏资料后刷新/换浏览器仍可读取，B 看不到 A 的收藏；重复操作无重复项，取消不影响资料或别人。
- 私人/被共享/公共/团队资料均能带准确来源进入收藏/最近；退出团队后相关资源和计数不再泄露。
- 工作台成功打开才写最近；失败、预取、只看首页详情不写；直接工作台链接也可记录。
- 同一资料去重排序；移除/清空不影响其他数据；迟到回执、退出和换账号不写错人。
- 300 个合法目标 CT 帧，60 个不同源帧有已发布掩码，显示 60/300 与 20%。
- 同帧多个标签不重复计；只读最新发布；本地草稿不入共享统计；失败读取不当 0。
- 序列 A 为 1/1、B 为 0/9，数据集为 1/10=10%，不是序列百分比平均的 50%。
- 新增 100 个无标注源帧后，60/300 更新为 60/400=15%；重复关联同一帧不增加分母。
- 无目标帧、未发布、加载失败、多帧不支持、部分统计各有不同显示，不制造假 100%。
- 首页显示设置只影响本人；模块错误不拖垮其余模块；切换显示不丢当前搜索/选择。
- 用真实规模资料核对首页请求量、掩码传输和服务器解码次数；决定是否必须随上线提供轻量汇总。
- 现有登录、上传、团队访问、共享、取消、未知写入与发布冲突回归通过。合成接口测试不代替真实后端验收。
