## 三、现有接口已经验证的内容

本次使用真实 Keycloak OIDC、Java 安全链、Orthanc、Python SEG 编解码和生产构建 Portal。没有业务 API 拦截、测试登录后门或直接写数据库。

完整串行场景通过：

1. A/B 两个临时账号正常登录。
2. 上传两帧全合成 CT；重复上传返回 `AlreadyStored`，不重复增加数据集实例。
3. 通过正常发布 API 为其中一帧添加一个像素标注；接口和首页均显示 **1 / 2 帧、50%**。
4. 私人资料共享前 B 无权访问，共享后 B 可读到相同统计。
5. 创建团队、添加成员、上传团队资料，另一成员正常访问；非上传者的 `canDelete=false`。
6. 相同 CT 导入另一个业务数据集，不继承原业务集的标注发布。
7. Java 会话退出与 Keycloak 退出完成，再登录需要输入密码。

标注统计继续使用已有接口：

```text
GET /api/me/annotation-stats
GET /api/datasets/{datasetId}/annotation-stats
GET /api/datasets/{datasetId}/segmentations/{seriesId}/stats
```

部署健康标记为 `annotationStatsApi: "v1"`。首页不读取完整 Labelmap 来计算比例；没有能力标记时保留资料库，并显示统计暂不可用。

**口径保持现有契约：**覆盖率是“非空掩码的受支持单帧 CT 帧数 / 受支持 CT 总帧数”，不是器官完整度、阴性帧检查完成率或审核通过率。`progress` 是当前服务器共享画布，`publishedProgress` 是已归档结果，不能混用。个人历史有效修改操作数也不能当成精确落笔数或完成率。

## 四、需要后端新增：本人收藏

希望支持：

- 列出本人收藏；收藏/取消收藏本人当前有权访问的数据集。
- 覆盖个人、被共享、公共及团队资料；返回准确来源，团队资料带团队 ID 和名称。
- 收藏属于本人，不修改数据集、共享或团队权限；有读取权即可收藏，不要求编辑权。
- 按当前会话 `issuer + subject` 隔离，不接收请求体指定操作者。
- 重复收藏/取消幂等；刷新、重新登录和换设备后仍能读取本人记录。
- 数据集删除或失权后，不返回旧名称、团队名、计数等摘要；先授权，再计数和分页。
- 能批量取得列表项的收藏状态，避免每个数据集额外查一次。

建议接口，仅供协商，**目前不存在，路径可由后端调整**：

```text
GET    /api/me/favorite-datasets
PUT    /api/me/favorite-datasets/{datasetId}
DELETE /api/me/favorite-datasets/{datasetId}
```

最小返回需要业务 ID、当前名称、来源、创建者、实例数和创建时间，收藏记录另带 `favoritedAt`。不要只给 ID，让前端遍历所有团队才能补名称。`instanceCount` 仍是实例数，不是 CT 帧数。

## 五、需要后端与工作台配合：最近打开

希望支持：

- 按本人最近成功打开时间倒序返回，按数据集去重。
- 移除一条记录、清空本人历史；清理不删除资料、收藏、标注或草稿。
- 包含个人及团队资料，失权后过滤旧摘要，其他用户不能读取本人的历史。
- 时间由服务端生成，操作者来自会话；明确重复上报、迟到请求和清空后的重试处理。
- 记录保留多久、最多多少条由双方确认，不默认永久保存。

**“打开成功”需要工作台负责人配合确认：**正常取得授权上下文且目标影像可用后上报。仅点击首页按钮、展开详情、预取或加载失败不记成功；直接链接进入工作台也应记录。

建议接口，仅供协商：

```text
GET    /api/me/recent-datasets
POST   /api/me/recent-datasets/{datasetId}
DELETE /api/me/recent-datasets/{datasetId}
DELETE /api/me/recent-datasets
```

返回资料摘要及服务器 `lastOpenedAt`。成功打开回执可使用 `eventId` 去重。首版能回到数据集即可；若要恢复到序列，再约定经服务端校验属于该集的序列引用，不能返回任意跳转 URL，也不在记录里存掩码、患者名或截图。

这项不能只由 Portal 在跳转前上报，否则会把“打开失败”也记录成成功。

## 六、本期不需要后端额外开发的内容

- 首页模块显隐、顺序、默认入口和现有显示偏好已经在前端完成；**不要求先有云端偏好 API**。跨设备同步设置以后另议。
- CT 覆盖率直接接现有统计，不新建任务系统，不要求上传前端笔画数，也不新造一个计算接口。
- 现有团队是独立资料库，不要求把团队改为个人共享对象。
- 任务指派、审核流、云端草稿同步、精确位置恢复、协作动态通知和保存复杂筛选不纳入这次最小接口需求。
- 若首页资料量很大，再评估批量统计摘要；当前不要为此重做全部统计或改变旧列表响应结构。

## 七、接口与部署注意

- 继续使用 Cookie 会话和动态 CSRF；所有新增写操作均校验 CSRF，资源授权由服务端完成。
- 新列表如需分页，请单独明确响应结构；不要无声改变旧列表 `total === items.length` 的既有含义。
- 说明稳定的错误状态或机器错误码；未登录、失权、参数错误、服务失败不能都返回空列表。
- 网关新增 `PORTAL_LOGOUT_ORIGINS`：部署控制的 JSON origin 数组，默认仍是原8081；更换 Keycloak 地址时同步配置，不能放宽前端目的地校验。
- 本次联调使用独立端口、realm、内存 H2 和影像卷，没有操作原数据；测试服务已停止，测试卷保留，凭证和 DICOM 未上传。
- 新版后端有历史 SEG 物理清理行为。真正部署前备份数据库和 Orthanc，并保持 Java / 网关 / OHIF 版本配套；代码回滚不能恢复已删影像。
- 原清理实现存在一项**静态审查、未动态复现**的并发引用风险：候选筛选后、实际删除前如果新增其他数据集引用，需后端核验。此项与首页接口无关，本次没有擅自改业务策略。

本次未验证完整 OHIF 画笔/多人 WebSocket 场景、真实患者大数据性能或临床质量；真实成员移除后的拒绝访问未在本次串行场景中执行，已有 Java/受控回归不应冒称该真实场景验收。
