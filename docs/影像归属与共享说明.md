# 影像归属与共享

在浏览器打开 http://127.0.0.1:8080/?version=dataset-access ，用 Keycloak 账号登录。若仍显示旧页面，按 Ctrl+F5。

## 现在的规则

- 原有胸部 CT 139 张、盆腔 CT 60 张作为两套公共影像保留，所有登录账号都能访问和修改。
- 每批文件或文件夹导入为一个新的私有影像集，只有创建者能访问。
- 共享以整个影像集为单位。共享给某个注册账号后，该账号获得全部已实现的操作权限，包括浏览、下载、改名、通过接口追加文件、继续共享和取消共享。
- 不区分只读和可编辑。创建者始终保留所有权；共享用户也可以取消自己或其他被共享用户的访问权限。
- 已加入极简逐切片掩码绘制器：绘制进度自动保存为个人草稿，点击“保存并上传”后发布 DICOM SEG。使用方法见同目录的《掩码绘制与DICOM-SEG说明.md》。

## 试一下

1. 账号 A 登录，点击“导入”，选择 DICOM 文件夹并填写影像集名称，点击“开始导入”。
2. 点击“打开影像集并共享”，或在“浏览”中选择“我的影像”。
3. 输入账号 B 的用户名（至少 2 个字符），点击“搜索用户”，再点击对应账号的“共享”。账号 B 需要事先注册，无需先登录过本项目。
4. 账号 B 登录后，在“共享给我的影像”里查看，改名或下载原始 DICOM。两个浏览器/无痕窗口可用来测试两个账号。
5. 点击“取消共享”后，被取消的账号再次请求该影像时会被拒绝。已下载到本地的文件无法收回。

## 三个程序各管什么

- Keycloak：注册、登录、账号身份。Java 使用单独的只读服务账号查询共享对象，不保存用户密码。
- Java：页面、接口、影像归属、共享权限。每次列举、预览、下载、导入、改名和共享均检查权限。
- Orthanc：实际 DICOM 文件。相同文件可以在物理仓库中去重，但每个影像集独立记录自己的切片清单。

业务界面请使用 8080。8042 是本机 Orthanc 管理入口，可直接管理底层文件，不经过 Java 的业务权限检查；目前保持仅本机访问。以后向别人提供访问时，应只公开业务入口。

## 数据放在哪里

- 归属及共享数据库：`legacy-local-task\work\dataset-access\runtime\dataset-access.mv.db`。
- DICOM 仍在原来的 WSL Orthanc 存储中。
- 停止 Java 后，可将数据库文件与 Orthanc 存储一起备份。只备份 DICOM 不会保存账户与影像集的归属关系。
- Java 使用内嵌 H2 数据库，无需再启动一个数据库服务。原来的 `start-demo.cmd` 仍可启动演示环境。

现有两套公共影像通过固定 199 张切片清单初始化一次。以后绕过 Java 直接导入 Orthanc 的影像，不会自动公开或自动归属给某个用户。

## 接口

所有业务接口使用登录会话；POST、PATCH、PUT、DELETE 还需要 `/api/session` 返回的 CSRF 请求头。

| 操作 | 接口 |
| --- | --- |
| 可访问影像集 | `GET /api/datasets` |
| 新建私有影像集 | `POST /api/datasets`，JSON `{ "name": "名称" }` |
| 改名 | `PATCH /api/datasets/{id}`，JSON `{ "name": "名称" }` |
| 切片清单 | `GET /api/datasets/{id}/instances` |
| PNG 预览 | `GET /api/datasets/{id}/instances/{instanceId}/preview` |
| 原始 DICOM | `GET /api/datasets/{id}/instances/{instanceId}/file` |
| 追加 DICOM | `POST /api/import`，multipart 的 `file` 和 `datasetId` |
| 搜索账号 | `GET /api/users?q=用户名` |
| 已共享账号 | `GET /api/datasets/{id}/shares` |
| 共享 | `PUT /api/datasets/{id}/shares`，JSON `{ "subject": "搜索返回的账号标识" }` |
| 取消共享 | `DELETE /api/datasets/{id}/shares/{subject}` |

旧的全仓库序列和预览接口已移除，不能利用它们绕过影像集权限。
