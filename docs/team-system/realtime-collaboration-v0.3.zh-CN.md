# CT 切片级自动编辑协议 v0.3

沿用 v0.2 的 WebSocket 外壳、房间、登录、团队权限、Outbox、序列操作序号和 SEG 后台归档；新增切片租约。无需手动申请整个序列的编辑权。

## 使用规则

- 开启实时协作后，开始绘制时自动获取所需原始 CT 切片，服务端成功授予后才向画笔交付鼠标事件，等待期间保留第一笔的事件。
- 同一数据集、同一序列内，不同原始 DICOM 切片可由不同页面同时编辑；同片只授予一个页面。被占用时显示编辑者，用户可直接改画其他未占用的切片。
- 持有者使用页面随机 clientId 和不透明 leaseId 区分，同账号不同页面也不能共占同片。租约 30 秒有效，每 10 秒检查续租；若已停笔至少 3 秒且没有待保存/待上传修改，则该次检查释放占用。也可点“释放占用的切片”。断线后没有续租，最迟在租约到期后允许其他人获取。
- 粒度是原始 CT DICOM 实例。MPR 非原始平面的笔画、球形及其他体积笔刷可能更改多张原始图，目前会保守地原子占用整个源切片集合；因此不同重建平面不保证可并画。新增、删除和改名标签也涉及整个序列，需全部切片可获取。

## HTTP 增量

公共前缀仍为 `/api/datasets/{datasetId}/segmentations/{seriesId}/collaboration`，所有写请求沿用 CSRF、登录身份和账户一致性校验。

`GET /state` 和 `GET /ops` 新增 `sliceLeases`：

```json
[{"instanceId":"Orthanc实例ID","heldBySelf":true,"subject":"用户ID","username":"医生A","leaseId":"仅自己的令牌","expiresAt":"ISO时间"}]
```

只返回尚未过期的记录；别人的 leaseId 不返回。`sliceLeases` 字段存在表示支持切片模式。WebSocket `room-state.capabilities` 新增 `slice-lease`。

`POST /slice-lease`：

```json
{"clientId":"页面ID","leaseId":null,"action":"acquire","instanceIds":["原始切片ID"]}
```

action 为 acquire、renew 或 release。返回本页面视角的全部有效切片租约。多片获取在一个事务中执行，任意一片被别人占用则全部失败（423），不会只拿到一半。影像来源无效为 400，现有访问控制照常执行。

`POST /ops/batch` 新增 `"sliced":true`，其他字段沿用 v0.2。Java 必须核对每个被改切片的有效持有者、clientId 和 leaseId；修改标签定义时核对全部源切片。旧客户端不传 sliced 时保留整序列租约逻辑，整序列租约和切片租约互斥。

## 保存与合并

- 房间仍使用连续全局 seq 做回放排序。不同切片的操作不会仅因全局 seq 前进而冲突；每张切片保存 modified_seq 和最后写入的租约，防止过期或离线旧画布覆盖新持有者的修改。
- clientOpId 继续幂等，重发内容和作者必须一致；所有操作先入业务数据库后广播，最终由后台生成整套 SEG。
- 前端收到别人操作时，检查它与本机 Outbox 和未入队修改涉及的切片是否相交。不相交则局部应用，保留本机笔画；相交或标签定义不兼容则保留私人草稿并提示冲突。
- 掩码渲染的签名按实例 ID 排序，并在异步本地写盘结束时以当前队列为准，避免同时到达的另一张切片更新被错当成下一笔本机修改。
- 本版对跨页面离线草稿恢复仍采用保守校验；无法证明可合并的草稿需导出后加载共享版本，不做隐式同片合并。

## 验证

回归覆盖不同切片的并发旧全局游标、同片互斥、多片获取回滚、越权切片写入、全局标签保护和过期令牌。浏览器测试用真实 139 张 CT、两个独立登录账号，验证不同切片并画、同片拒绝、切换未占用切片继续画、双方实际掩码显示及刷新恢复；保留 v0.2 连续三笔和 MPR 三视图像素比较。
