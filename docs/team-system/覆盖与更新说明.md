# 团队系统增量覆盖说明

日期：2026-11-02。对应 `team-library-v1` / `personal-irrevocable-v1`。

## 直接覆盖到原项目

基线是之前的 `medcollab-fullstack-github-2026-11-01.zip` 完整源码包。这个增量 ZIP 内直接是仓库根目录的文件路径：`frontends/`、`backend/`、`gateway/`、`docs/` 和 `README.md`，没有额外套一层 `medcollab/`。

将 ZIP 解压出来的文件按原路径覆盖到已经包含 `frontends/`、`backend/`、`gateway/` 的项目根目录，再查看差异并提交即可。每个文件为完整的新版本；没有文件删除，也无需删除整个旧目录。所有与基线相同的文件均未重复打包。

```sh
git status --short
git diff --stat
git add .
git commit -m "Add team imaging library and irrevocable personal sharing"
git push
```

`增量文件清单.json`（本目录下）记录每个文件相对上一版的新增/修改状态、覆盖前后 SHA-256；本次源码包基线的 ZIP SHA-256 也在清单中。它便于确认覆盖范围，不会修改你的仓库。

## 这次包含的功能

- 创建/搜索团队、邀请码加入、搜索已有账号拉人、移除成员、退出与移交组长。
- 独立团队影像库；成员能上传、读取、标注，只有当前成员中的数据集创建者能删除自己的数据集。
- 团队数据集软删除；离队或被移除后，原图、DICOMweb、SEG 等入口重新校验访问权限。
- 个人共享确认后不可撤销。原 DELETE 共享接口返回 409，前端移除撤销操作并显示确认提示。

## 团队接口文件

主要文档：`docs/frontend-handoff/team-library/团队系统接口.md`。同目录提供 `openapi.json`、`contracts.ts`、`request-examples.ts`。Portal 和 OHIF 的交接文档中保留对应副本，方便各自开发者使用。

## 覆盖后构建和部署

只更新 GitHub 源码时，完成提交和 push 即可。要让运行中的服务使用新代码，先构建：

```sh
node scripts/build.mjs portal
node scripts/build.mjs backend
```

随后停止原 Java 与网关进程，并按原项目方式重新启动：

```sh
node scripts/start-backend.mjs
```

另一个终端：

```sh
node scripts/start-gateway.mjs
```

本次 OHIF 运行代码、依赖与锁文件未变，无需重建已存在的 OHIF 产物。环境配置、已生成的 Keycloak 凭据、Python 环境和业务数据库继续使用原路径。部署既有实例时，停 Java 后备份现有业务数据库；新版本启动会自动补充团队表和软删除列。Java 重启后需要重新登录。

访问 `http://127.0.0.1:8080/teams`，或者登录 Portal 后点“团队影像库”。旧的本机 WSL 启用器和 JAR 未包含在 GitHub 源码增量中；本仓库沿用此前的可移植构建/启动脚本。
