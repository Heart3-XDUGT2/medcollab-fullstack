> 2026-11-02 团队影像库增量：先读 [团队库与个人不可撤销共享](./team-library/团队系统接口.md)。该版本增加团队 API，并禁止个人共享撤销；旧的撤销说明不再适用。覆盖后按仓库的 scripts/build.mjs 重建并重启后端和网关。

核对日期：2026-11-01。范围：当前已接入真实服务器的 Portal、Keycloak 自定义主题、OHIF 工作台；包含折叠保存面板与标签颜色空值修复。

这份文档以当前 Java Controller/Service、Portal 请求适配器、网关和 DatasetWorkspace 的代码为准。交接包中的 `contracts.ts` 提供类型，`request-examples.ts` 提供请求示例。编号与令牌均需从实际响应取得。

## 1. 接手后先守住这些约定

可以重做排版、配色、按钮位置和交互，但应继续复用现有请求与工作台服务。以下行为不能随着 UI 优化被删掉：

1. 业务请求走同源 `/api/...`，由 Java 检查账户与影像集权限。浏览器不直接请求整台 Orthanc，也不持有其密码。
2. 真实登录/注册是跳转到 Keycloak 的主题页面。Portal 没有用户名密码 JSON 登录接口，也不自行保存 JWT。
3. 每次写请求先重新读取 session，核对 `issuer + subject`，使用当次 CSRF；切换账号和页面上下文后停止旧操作。
4. `datasetId`、Orthanc `seriesId/instanceId`、DICOM Study/Series/SOP UID 是不同编号，不能互换。
5. 工作台 CT 通过 DICOMweb 读取像素和空间信息；PNG 仅是另一个旧预览接口，不能替代工作台输入。
6. 掩码草稿保存在当前浏览器 IndexedDB；点发布后才由 Java 编码为 Labelmap SEG 写入 Orthanc。
7. 发布的是完整快照。遗漏切片代表背景，不能把增量掩码当完整快照提交。
8. 发布必须保留旧版本检查和幂等请求编号。结果不明时冻结原内容与编号，不能创建新编号自动重发。
9. 本机有草稿时，共享新版本只能提示，不能自动覆盖本机绘制；409 不能用强行更新版本号绕过。
10. 页面显示了某个工具，不等于该工具结果已有保存接口。当前成品链路保存 Labelmap 掩码；箭头、测量等尚未接入。

## 2. 实际架构、地址和页面入口

```text
浏览器：Portal / OHIF / Keycloak 登录主题
    │ Cookie + 动态 CSRF（写操作）
    ▼
8080 统一网关：Portal 静态资源、OHIF /imaging/、API 代理
    ▼
8082 Java（WSL）：登录会话、权限、影像集/共享、发布版本、DICOM 编码调用
    ├── 8081 Keycloak：账号、登录注册、SSO
    └── 8042 Orthanc + DICOMweb：原始 DICOM、发布的 DICOM SEG

浏览器 IndexedDB：个人掩码草稿；不会自动上传给以上服务器
```

| --- | --- | --- |

### 2.1 Portal 运行配置

正式网关返回：

```js
window.config = { medcollab: {
  apiEnabled: true,
  authOrigin: 'http://127.0.0.1:8080',
  logoutOrigins: ['http://127.0.0.1:8081'],
  workspacePath: '/workspace',
  publicSamplePath: null
} };
```

配置来自部署文件，不来自地址栏参数、localStorage 或用户输入。`workspacePath` 必须是同源绝对路径，不带 query/hash；构造参数使用 `buildWorkspaceUrl`。独立 Portal 的 `public/config.js` 默认不启用真实 API，这与正式网关动态配置有意不同。

`authOrigin` 用于认证目的地，不是任意跨域 API base。业务适配器仍请求相对 `/api`。Java 当前没有通用 CORS；本地开发应配置受控代理并保留既有 8080 登录回跳，最终在正式同源入口验收。

## 4. 登录、注册、用户信息、退出

### 4.1 已实现接口

| 方法 | 路径 | 成功响应 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/session` | 200 `Session` | 匿名也可读取；返回当前身份和 CSRF |
| GET | `/auth/login` | 302 导航 | Java → Keycloak 登录 |
| GET | `/auth/register` | 302 导航 | Java → Keycloak 注册 |
| POST | `/api/logout` | 200 `{logoutUrl:string}` | 清除 Java 会话，然后导航完成 Keycloak SSO 退出 |
| GET | `/api/health` | 200 `Health` | Java 活跃状态与 `workspaceApi` 能力标识 |
| GET | `/api/orthanc/status` | 200 `OrthancStatus` | 登录后检查 Orthanc，计数是当前用户可见实例去重数 |

```ts
type Session = {
  loggedIn: boolean;
  username: string | null;
  issuer: string | null;
  subject: string | null;
  csrfToken: string;
  csrfHeaderName: string;
};
```

`username` 只用于展示。稳定身份使用 `issuer + subject`。`/api/session` 200 不等于已登录，必须检查 `loggedIn`。

Cookie 为 `MEDICAL_DEMO_SESSION`，HttpOnly、SameSite=Lax，由浏览器管理；当前空闲超时 30 分钟。请求使用 `credentials:'same-origin'`、`cache:'no-store'`；Portal JSON 请求还用 `redirect:'error'`。读写都不能把 HTML 登录页当 JSON 解析。

所有 POST/PUT/PATCH/DELETE 都须使用最新 session 的动态 `csrfHeaderName/csrfToken`。不要写死 token，不在 localStorage、URL 或日志保存凭据。写请求开始时还要保存操作身份，发送前复核；身份变化就停止旧操作。`publish-labelmap` 和 `export-labelmap` 继续附 `X-Medcollab-Issuer`、`X-Medcollab-Subject`；当前后端在提供这些头时会核对身份，缺省仍兼容，现有 OHIF 的保护不能删掉。

登录完成：Keycloak → Java `/login/oauth2/code/keycloak` → Java `/` → 网关 `/home`。登录失败保留 `?authError=1`，Keycloak 不可用为 `?authError=unavailable`，退出回到 `/?logout=1`。`/oauth2/authorization/keycloak` 和 OIDC callback 是协议内部路径，不自行构造 code/state。

退出时先 POST `/api/logout`，清理页面中的当前用户数据和待发送操作，再导航到响应的 `logoutUrl`。沿用 Portal 的允许 origin 校验；不能只隐藏头像，也不能任意跳转未知退出 URL。保存在原身份下的 IDB 草稿不因退出而自动删除。

### 4.2 “给 Keycloak 套皮”的实际维护方式

真实登录页面使用 Keycloak 的 FreeMarker 主题，不是把 Portal 的 React 密码表单 POST 到 Java。

- `login.ftl` 的 action 保留 `${url.loginAction}`，字段包括 `username`、`password`、`credentialId`。
- `register.ftl` 的 action 保留 `${url.registrationAction}`，继续使用 Keycloak 用户属性表单与 `password`、`password-confirm`。
- 注册、返回登录、找回密码链接使用 Keycloak 生成的 URL；保留会话状态、字段错误和服务端校验。
- 修改样式后，按需运行 `prepare-theme.mjs` 生成 CSS/字体/图标，再由 `keycloak-theme.mjs` 部署和选择主题；仅重建 Portal 不会同步真实登录主题。
- 这两个脚本涉及 Keycloak 部署配置；先审查改动再运行。普通 CSS 维护不需更改 realm、client secret 或认证协议。

## 5. Portal 影像集、导入、共享接口

以下路径均相对于 8080。除 `/api/session`、`/api/health` 外需要登录；写入还需要 CSRF。业务 JSON 成功通常为 200，创建不是 201，删除共享不是 204。

| 方法 | 路径 | 请求 | 200 响应 |
| --- | --- | --- | --- |
| GET | `/api/datasets` | 无 | `Items<Dataset>` |
| POST | `/api/datasets` | JSON `{name}` | `Dataset` |
| PATCH | `/api/datasets/{id}` | JSON `{name}` | `Dataset` |
| GET | `/api/datasets/{id}/instances` | 无 | `Items<Instance>` |
| GET | `/api/datasets/{id}/instances/{instanceId}/preview` | 无 | `image/png` 字节，旧预览用途 |
| GET | `/api/datasets/{id}/instances/{instanceId}/file` | 无 | `application/dicom` 字节 |
| POST | `/api/import` | multipart `file`、`datasetId` | `ImportResult` |
| GET | `/api/users?q=...` | 查询用户名，2–100 字符 | `Items<User>`，最多 20 个候选 |
| GET | `/api/datasets/{id}/shares` | 无 | `Items<User>` |
| PUT | `/api/datasets/{id}/shares` | JSON `{subject}` | `{success:true}` |
| DELETE | `/api/datasets/{id}/shares/{subject}` | 无 body | 已停用：409，不移除个人共享 |

```ts
type Items<T> = { items: T[]; total: number };
type Dataset = {
  id: string; name: string;
  access: 'owner' | 'shared' | 'public';
  ownerUsername: string; instanceCount: number; createdAt: string;
};
type Instance = { id: string; instanceNumber: string };
type User = { subject: string; username: string };
type ImportResult = { status: 'Success' | 'AlreadyStored'; id: string };
```

`createdAt` 为 ISO 日期；`instanceNumber` 是可空字符串，不能当数组下标或连续页码。名称去除首尾空白后为 1–200 字符，可重名，保存在 Java 业务数据库，不改 DICOM PatientName。`instanceCount` 是 DICOM 实例数，不是患者数、三维病例数或标注进度。

`/api/datasets`、instances、shares 当前没有 page/size 分页；`Items.total` 是当前数组长度，现有 Portal 会验证 `total === items.length`。界面本地搜索不等于后端新增筛选。DICOMweb 的 limit/offset 是另一组接口，不可混淆。

### 5.1 当前权限语义

公共集对所有登录用户可读可编辑；私有集的上传者及共享成员可读、导入、改名和编辑。当前个人共享可编辑、可继续共享；2026-11-02 起确认后不可撤销，所有者和共享成员均不能移除共享。公共集调用共享管理会返回 400（已对所有登录用户开放）。

`access` 表示当前用户与影像集的关系，`owner` 不是“只有我可见”的隐私设置。UI 可以根据它解释来源，权限最终由 Java 检查。访问不到的数据集/实例通常统一返回 404，不区分不存在和无权限。Keycloak roles 保留，目前不要自行增加只读/审核员规则或仅凭 role 放行。

### 5.2 文件夹上传如何保持兼容

当前 Portal 选择文件夹后取得多个 File，先 POST `/api/datasets`，随后逐文件 POST `/api/import`。每次只传一个 `file` 和目标 `datasetId`，使用 FormData；不要手工设置 multipart Content-Type/boundary。没有“传本机文件夹路径让服务器读取”的接口，也没有现成 ZIP 批量上传接口。

限制：默认单文件非空且不超过 1 GiB（1,073,741,824 字节）；Spring multipart 单请求默认 `1025MB`，仅为一个文件加表单开销，不是文件夹额度。两个各 600 MiB 的文件可分别导入，文件夹总和不套用单文件上限，仍受实际磁盘等部署资源约束。当前上传队列串行，有进度与取消保护，优化并发前必须保留身份/权限变化时停止后续请求的行为。

Portal 以 `upload-policy.ts` 统一限制及显示，单文件导入客户端期限为 30 分钟；网关仅 `/api/import` 上游等待和 POST 请求体接收上限为 30 分钟，其他请求体保留 5 分钟、请求头 60 秒。HTTP 408 与网络/取消/5xx 一样按导入结果未知停止队列，不自动重试。后台配置为 `IMPORT_MAX_FILE_BYTES`（默认 1073741824）、`IMPORT_MAX_REQUEST_SIZE`（默认 1025MB）与 `ORTHANC_IMPORT_TIMEOUT_SECONDS`（默认 1800）；服务端权威，Portal 不自动发现修改，部署调节须同步各层。

本轮只放宽文件导入，不放宽 SEG 或工作台源 CT 原有 64 MiB 安全限制，也不承诺任意大型 DICOM 都能被当前工作台解析。

- `Success`：新增底层 DICOM 并建立业务成员关联。
- `AlreadyStored`：Orthanc 已有相同对象，当前影像集仍会获得关联，应计为成功的“已存在”。不同账号可以各自有独立影像集，底层物理去重不等于自动共享。
- 同 DICOM 标识但文件字节不同会返回 409，不应强制覆盖或修改 UID 后自动重试。
- 取消/失败不会回滚已建立的影像集和已上传实例。超时、断网、5xx、取消后的在途请求可能结果未知；先刷新列表核对，不自动重建或重传。

接口面向 DICOM；扩展名不是唯一判断依据。能导入一个 DICOM 对象不代表 OHIF 工作台支持它的模态。当前工作台限定普通单帧 CT；NRRD/NIfTI、PNG、STL、OBJ 等没有通用上传/读取接口。外部 SEG 即使进入 Orthanc，也不会自动登记成当前业务集的发布版本，不要用 `/api/import` 代替下面的发布接口。

## 6. 从“打开工作界面”进入正确 CT

Portal 继续调用 `buildWorkspaceUrl(config, dataset, intent)`，得到：

```text
/workspace?datasetId=<业务ID>&access=owner&intent=view&returnPath=%2Fhome
```

当前启动器真正使用 `datasetId`，其余值是界面上下文；`intent=view` 不会建立新的只读权限。不要凭 access/intent 允许读写。

1. 启动页 GET `/api/datasets/{datasetId}/workspace`。
2. 一个序列自动打开，多序列先选择；没有支持的 CT 则提示，不回退到无关公开样本。
3. 从响应构造 `/imaging/medcollab/medcollab?datasetId=...&seriesId=...&StudyInstanceUIDs=...&SeriesInstanceUIDs=...&lng=zh-CN`。
4. OHIF 再核对 session、获授权源清单、UID 和 FrameOfReferenceUID；待影像就绪后启用编辑。
5. 返回固定可信 `/home`，重新读取会话和列表。改变返回路径时同时修改双方约定，不能允许任意外站重定向。

```ts
type Launch = { datasetId: string; series: Array<{
  id: string;                    // Orthanc 系列 ID → 路径中的 seriesId
  studyInstanceUID: string;       // DICOM Study UID
  seriesInstanceUID: string;      // DICOM Series UID
  frameOfReferenceUID: string;
  description: string;
  instanceCount: number;
}> };
```

`GET /workspace` 是 HTML 页面；`GET /api/datasets/{id}/workspace` 才是 JSON 数据。前端不要把同名 workspace 混用。

## 7. OHIF 输入：受权限控制的 DICOMweb

设 `DW = /api/datasets/{datasetId}/dicomweb`。此组 GET 需要 Java 登录会话和精确影像集成员权限；query 参数编码、UID 来自 launch 响应。

| 方法 | 路径（相对 DW） | 返回 |
| --- | --- | --- |
| GET | `/studies` | QIDO 检查列表 |
| GET | `/studies/{study}/series` | QIDO 序列列表 |
| GET | `/studies/{study}/series/{series}/instances` | QIDO 实例列表 |
| GET | `/studies/{study}/metadata` | 当前获授权成员的 DICOM 元数据 |
| GET | `/studies/{study}/series/{series}/metadata` | 同上，限制到序列 |
| GET | `/studies/{study}/series/{series}/instances/{sop}/metadata` | 指定实例元数据 |
| GET | `/studies/{study}/series/{series}/instances/{sop}` | WADO-RS DICOM 字节，保留实际 Content-Type |
| GET | `/studies/{study}/series/{series}/instances/{sop}/frames/1` | 帧像素，可能为 multipart/related |
| GET | `/studies/{study}/series/{series}/instances/{sop}/bulk/{tagPath}` | 受限 BulkData |

QIDO/metadata 返回 `application/dicom+json` 数组，不使用 `{items,total}`。字段是 DICOM tag，如 `"0020000D":{"vr":"UI","Value":["..."]}`；不要按普通扁平 JSON 解析。帧/文件响应交给现有 OHIF loader，不能当 JSON 或 PNG。

QIDO 已支持精确 `StudyInstanceUID`、`SeriesInstanceUID`、`SOPInstanceUID`、`Modality`（也接受对应 tag 编号）过滤；值可逗号分隔。支持 `offset` 0–100000、`limit` 0–10000，默认 offset=0、limit=10000。metadata 不应用这套列表分页。不支持通用模糊/通配搜索、任意 PACS 检索或 STOW 写入；配置中的 include-field 能力不代表实现了任意扩展参数。

`{study}/{series}/{sop}` 是 DICOM UID，不能换成 Orthanc 哈希 ID。当前帧入口只支持 `frames/1`；bulk tagPath 只允许标准 tag/序列项路径（如 `7FE00010`），不要构造任意代理 URL。metadata 的 BulkDataURI 已重写为同源受控路径。

同一 DICOM Series UID 也可能只在业务集里包含部分切片。Java 只返回该业务集的精确成员；前端不能推导另一条裸 Orthanc 路径来补齐未获授权切片。

维持 `medcollab-server.js` 的同源 qidoRoot/wadoRoot、`wadors`、dataset 范围、数据源名 `medcollab` 和路由 basename。若只换外观，不需要动这一层。

## 8. OHIF 输出：多标签掩码、发布与导出

设 `SEG = /api/datasets/{datasetId}/segmentations/{seriesId}`，其中 seriesId 为 Orthanc 系列 ID。

| 方法 | 路径 | 用途/响应 |
| --- | --- | --- |
| GET | `/api/datasets/{datasetId}/segmentation/sources` | `Items<SourceImage>`，全部可标注 CT 源信息；按 seriesId 选择 |
| GET | `SEG/labelmap` | 200 `{status:SegmentationStatus,data:Labelmap}`，最新共享成品 |
| GET | `SEG/status` | 200 `SegmentationStatus`，轻量版本查询 |
| POST | `SEG/publish-labelmap` | JSON `LabelmapRequest` → 200 `SegmentationStatus` |
| POST | `SEG/export-labelmap` | 同结构 JSON → 200 `application/dicom`，临时编码当前内容 |
| GET | `SEG/file` | 200 `application/dicom`，下载已发布最新成品；无成品时 404 |

```ts
type SourceImage = {
  id: string; instanceNumber: string;
  seriesId: string; seriesDescription: string;
  rows: number; columns: number; sopInstanceUid: string;
};
type Segment = { number: number; label: string; color: number[] }; // RGB，3 个整数
type Mask = { instanceId: string; runs: number[] };
type Labelmap = { segments: Segment[]; masks: Mask[] };
type LabelmapRequest = {
  expectedPublishedVersion: number;
  publicationId: string;
  label: string;
  data: Labelmap;
};
type SegmentationStatus = {
  seriesId: string; rows: number; columns: number;
  publishedVersion: number; publishedBy: string | null;
  publishedAt: string | null; label: string; orthancId: string | null;
};
```

尚未发布时 `publishedVersion=0`，publishedBy/publishedAt/orthancId 为 null，GET labelmap 的 data 为 `{segments:[],masks:[]}`。现有 OHIF 会为绘制创建默认标签；不能把初始空返回当服务器错误。

### 8.1 JSON 请求与真正的 DICOM 文件是两层

浏览器把标签名称、RGB 和掩码游程 JSON 发送给 Java；不是前端把 `.dcm` 作为 body 发到这些发布接口。Java 使用源 CT 的体素/空间信息，通过 highdicom 编码为 `.dcm` 的 Labelmap SEG，再写 Orthanc。

成品为 SegmentationType=LABELMAP、SOP Class UID `1.2.840.10008.5.1.4.1.1.66.7`、8-bit 标签、Explicit VR Little Endian (`1.2.840.10008.1.2.1`)。标签名、颜色、源引用和空间坐标保留。RGB/CIELab 换算可能有 1 个色值的取整差异，像素标签必须一致；旧 Binary SEG 可读。

`POST export-labelmap` 编码的是当前请求内容，不上传 Orthanc、不新增共享版本、不创建 Java 草稿；当前实现不以 expectedPublishedVersion 锁定导出。`GET SEG/file` 下载的是已登记发布文件，二者不可用同一个“保存成功”提示混淆。

### 8.2 游程、坐标与限制

每张 mask 的 `runs = [start,length,labelNumber,...]`。以源 DICOM 切片像素数组为准，`index = row * columns + column`，从 0 开始；颜色与屏幕缩放/旋转不改变像素索引。

例如 `[513,3,1,1024,2,2]` 表示像素 513–515 属于标签 1，1024–1025 属于标签 2。背景值为 0，不上传背景；游程必须按位置升序、不重叠、不越界、长度为正，标签号必须存在于 segments。不要按屏幕坐标直接写游程，不要给同一实例重复列 mask。

请求是整个序列的完整快照：未列出的切片、未覆盖像素都变为背景。首次发布至少有一个前景像素；已有成品后允许 masks=[] 清除成品，但仍须提供合法标签。

当前每序列一个分割，可包含 1–64 个标签，编号唯一且在 1–255，单层 Labelmap 不支持同像素重叠标签；背景为 0。颜色是三个 0–255 整数，不能发送 RGBA 的四项。请求 label 与每个标签 label 为去首尾空白后的 1–64 字符，不能有控制字符。

当前上限同时生效：序列最多 2048 张；源尺寸一致；总 runs 数字项最多 1000000；codec 工作 JSON 最大 16 MiB；codec 总体素最多 134217728；SEG 文件最多 64 MiB。Service 的预检体素限制更宽（256×1024×1024），因此不应只按预检值承诺可处理大小。具体体素、坐标和单帧 CT 校验还会在编码阶段执行。

### 8.3 正确的发布过程

1. 取得草稿基于的 `publishedVersion`，作为 expectedPublishedVersion；绘制期间不能擅自改成服务器最新值。
2. 先把完整草稿持久化到 IndexedDB，生成并保存 publicationId（现有实现使用 crypto.randomUUID）；合法格式为 16–80 位字母、数字、连字符。
3. 再持久化 `publishAttempted=true` 及冻结的完整请求；停用会修改这份请求的绘制操作。
4. 重新读取 session，核对 issuer/subject，附当次 CSRF 与两个身份头后发送。
5. 成功响应后才清除该草稿内容并留下 revision 墓碑，更新共享版本和界面。
6. 响应丢失/5xx/结果未知：保留原内容、expectedPublishedVersion、publicationId；由用户选择重试，同编号同内容同身份才能取得原发布回执。不能变更内容后沿用编号，也不能换新编号掩盖未知结果。
7. 409：可能是共享版本已变化、发布编号冲突或账户变化。显示服务端原因，保留草稿；不能简单覆盖 expectedPublishedVersion 后再提交。

当前已有发布版本历史登记，但没有面向前端的“历史版本列表/任意版本读取/回滚”接口。不要把数据库内部版本记录当成已经开放的功能。

## 9. 本机草稿与用户间同步

### 9.1 IndexedDB 协议

| 项目 | 当前约定 |
| --- | --- |
| Database / version | `medcollab-mask-drafts` / 1 |
| Object store / keyPath | `drafts` / `key` |
| OHIF key | `JSON.stringify([issuer,subject,datasetId,seriesId + ':ohif-labelmap'])` |
| record | `{key,revision,draft}`；不存在时 revision=0、draft=null |
| draft | `{data,label,baseVersion,sourceFingerprint,publicationId,publishAttempted?,schema:1,updatedAt}` |
| fingerprint | 源 id/sopInstanceUid/rows/columns 排序后的 JSON，使用现有 `maskDrafts.fingerprint` |
| 读写入口 | `window.maskDrafts.key/fingerprint/read/write` |
| 写入 | `write(key,expectedRevision,draft)`，事务提交后才认为已保存 |
| 清除内容 | `write(key,expectedRevision,null)`，保留递增 revision 的墓碑 |

保存的草稿 payload 没有身份凭据；身份在命名空间 key 中。不要把 token、Cookie 或密码写进草稿。不同来源/端口的 IndexedDB 不互通，因此不要随意更换正式站点来源来“优化部署”，否则用户原草稿不会自动跟过去。

不能用普通 put/delete 替换 CAS 写入：两个标签页可能交错保存；删除整条记录会使旧页面误以为是全新草稿并覆盖。旧极简单标签 IDB 草稿仅在 OHIF record revision==0 且来源指纹匹配时复制升级；发布后的墓碑必须阻止旧草稿再次复活。新的 schema/key/db 迁移要显式设计和测试，不能直接清库。

当前改动去抖约 700 ms 自动保存；保存的是浏览器本地完整快照。IndexedDB 失败时显示“未保存”，不能伪装成功。修改 UI 不应改变这些语义。

### 9.2 共享更新

已打开的工作台约每 15 秒查询 SEG/status，同时复核 session。没有本机修改时可加载新的共享版本；有本机草稿时提示 newerVersion，不覆盖它。用户手动加载共享版本时沿用替换确认与导出建议。

目前没有 WebSocket 画笔直播、掩码增量广播、自动合并或编辑租约。其他用户看见的是已发布成品；公共集和有共享权限的私有集走相同发布机制。

同一浏览器的标签页共享登录 Cookie，不能靠两个 tab 保持两个独立账号。双账号验证使用独立浏览器 context/配置，或两个浏览器；草稿仍按完整身份隔离。失去权限时停止编辑，不能把原账户草稿移交给后来登录的人。

## 10. UI 与工作台服务之间的接口

改保存面板时，继续从 `servicesManager.services.datasetWorkspaceService` 或扩展 utility 的 `getDatasetWorkspace()` 获得现有对象。不要在 React render 里 new Workspace、重新 bind，或再创建一份分割。

| 成员 | 用法 |
| --- | --- |
| `state` | ready/busy/dirty/local/username/datasetId/seriesId/version/savedAt/message/error/newerVersion |
| `subscribe(listener)` | 状态改变通知，返回清理函数；组件卸载要调用 |
| `saveDraft()` | 手动本机草稿保存，不调用 Java 草稿接口 |
| `publish()` | 完整冻结、发布、重试和版本处理 |
| `exportFile()` | 编码并下载当前内容，不发布 |
| `loadLatest()` | 获取共享最新版本，处理本机替换提示 |

这些是当前前端内部接口，不是 HTTP API，也不是独立 npm SDK 的稳定版本承诺。纯 UI 改造尽量只依赖表中成员，别调用 private capture/json/restore 或直接修改 service.state。示例验证脚本访问内部对象只用于检查，不是产品代码模板。

按钮保留 `!ready || busy` 的禁用规则；错误不要只写 console。`local=true` 表示有未发布本机草稿，不能显示“已共享”；`dirty=true` 表示本地持久化尚未完成。数据加载中不要假报已同步。

折叠面板只保存 UI 偏好：localStorage `medcollab:dataset-bar:expanded`，默认收起。保留 aria-expanded/aria-controls、键盘操作、错误入口、保存状态；不要折叠时停止 service 或取消自动保存。面板按键需避免触发 OHIF 全局快捷键。

已修复的空值问题：`getSegmentColor(activeViewportId,...)` 在空视图或布局切换时可以返回 null。当前 `segmentColor()` 会寻找实际挂载分割的视图，并在短暂脱离显示时保留已知颜色。重构不能恢复为直接 `.getSegmentColor(...).slice(...)`。未知新标签尚无颜色时提示等待，不伪造颜色覆盖用户设置。

`bind()/close()`、generation、stopped、会话检测和事件取消由 mode/service 管理。不要为了界面即时刷新去删除它们；它们阻止迟到请求写入新页面/新账号。离开前保留 beforeunload 与正在保存/发布的提示。

## 11. 错误、兼容接口和未实现范围

错误通常为非 2xx + `{error:string}`；请求格式/代理层异常也可能不是可解析 JSON，应有兜底。保留服务端信息，不仅按数字给一个“失败”。

| 状态 | 当前常见含义 | 前端行为 |
| --- | --- | --- |
| 400 | 字段、游程、坐标/模态、标签限制；公共集不需共享 | 提示具体原因，不自动重试 |
| 401 | 未登录、会话过期 | 停止写入，保护本机内容，重新认证 |
| 403 | CSRF 或请求校验失败 | 重新获取 session，确认身份；不静默重放写请求 |
| 404 | 无此资源或没有权限；也可能仅搜索的共享对象失效 | 结合接口上下文处理，不能一律清空所有影像 |
| 409 | 版本冲突、请求编号冲突、身份变化、DICOM UID 内容冲突；本地 CAS 也用 409 标记 | 保留内容，按具体来源处理，不自动覆盖 |
| 410 | 旧 Java 草稿写接口已停用 | 迁移/使用 IndexedDB |
| 413 | 单文件/编码输出过大等限制 | 不把所有 413 固定解释为同一资源上限 |
| 415 | Content-Type 或文件格式不支持 | 不通过改扩展名规避 |
| 423 | 发布事务锁等待/超时 | 保留草稿，稍后明确重试；不是已实现租约系统 |
| 500/502/503/504、断网/超时 | Java/Orthanc/代理失败，写结果可能未知 | 不自动当作确定失败并重复写入 |

### 11.1 保留的旧接口（OHIF 新功能不要接到这里）

| 方法 | 路径（相对 SEG） | 当前情况 |
| --- | --- | --- |
| GET | 空路径，即 SEG | 旧单标签 `Workspace`，masks 为 `[start,length]` 对 |
| POST | `/publish` | 旧单标签 `PublishRequest`，当前共用 codec 输出单标签 Labelmap SEG；请求仍是旧的成对游程 |
| PUT | `/draft` | 410，禁止恢复服务器草稿写入 |
| GET | `/legacy-draft` | 只读旧 Java 草稿 `LegacyDraft`；无记录可为 200 空 body |
| DELETE | `/legacy-draft?revision=...` | 本地成功迁移后确认清除旧记录，成功 204 |

旧单标签与多标签接口的 runs 格式不同：对 `[start,length]` vs 三元组 `[start,length,number]`，不能互发；也不能用旧接口把多标签结果降成单标签覆盖。新版默认使用 `/labelmap`、`/publish-labelmap`、`/export-labelmap`。

仍未开放：通用文件存储、ZIP 导入、Study 全仓库查询、STOW 成品登记、SR/RTSTRUCT 发布版本、测量箭头保存、STL/OBJ 存取、任意历史版本列表/回滚、训练导出、模型训练、实时共同绘制、细分审核角色。浏览器显示的三维体绘制/表面不是已经保存的三维文件。
