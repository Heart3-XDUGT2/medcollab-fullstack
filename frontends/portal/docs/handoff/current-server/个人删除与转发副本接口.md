# 个人删除、转发副本与 NIfTI 提示（2026-11-06）

本增量覆盖早期“共享同一份个人数据集”的规则。部署后以 `/api/health` 的 `sharingPolicy=personal-forward-copy-v1`、`datasetDeletionApi=unreferenced-reclaim-v1`、`niftiImport=unsupported` 为准。Cookie 登录、动态 CSRF、DICOMweb、Labelmap SEG 及团队成员权限沿用原协议。

## 用户规则

- 个人共享是转发独立副本。接收者获得新的业务数据集 ID，`access=owner`，拥有重命名、追加文件、标注、转发和删除权限。CT、已发布的当前 SEG 以及服务器已接受的当前掩码被复制为当时的快照；之后双方编辑互不影响。未上传的 IndexedDB 草稿不会转发。
- 原始 DICOM 文件可在 Orthanc 共用同一个物理对象，Java 分别登记持有关系。独立业务副本不等于重复保存一遍 CT。
- 同一转发链中，接收者已有活跃副本时返回它的 ID，不覆盖其名称、文件或标注。重复转发也不会刷新旧快照。接收者删除后，可再次收到新副本。A 删除后，B 也可以把副本转发回 A。
- 独立上传相同文件仍可建立不同业务数据集；上述去重只针对转发链，底层存储去重仍由 Orthanc 及字节核对完成。
- 转发不能撤回对方的副本。接收者可以删除自己的副本。团队影像库继续共同编辑同一团队数据集，本增量不更改团队删除入口及其原有逻辑删除规则。
- 公共示例不可个人删除或转发。个人收到的副本显示在“我拥有的”，不再依靠 `access=shared` 访问发送者原 ID；团队的 `shared` 关系含义保留。

## API

所有业务成功为 HTTP 200，JSON；列表仍为 `{items,total}`。写入前重新 `GET /api/session`，比较 `issuer+subject`，使用返回的 `csrfHeaderName/csrfToken`，并保留账号切换和卸载取消边界。结果未知时不得自动重发。

### `GET /api/datasets`

个人列表项增加 `canDelete: boolean`。只有自己的非公共个人集可删除。前端兼容旧服务时把字段缺失视为不可删除，不能仅凭 `access=owner` 推断删除能力。该列表不混入团队数据集。

### `PUT /api/datasets/{id}/shares`

请求仍为 `{ "subject": "Keycloak 用户 ID" }`，路径和方法不变。

```json
{"success":true,"recipientDatasetId":"接收者业务数据集ID","alreadyOwned":false}
```

`alreadyOwned=true` 表示复用对方当前持有的本链副本，未覆盖其内容。`recipientDatasetId` 只能由接收者以自己的身份打开，发送者不能拿该 ID 读取对方。不能转发给自己。公共/团队集返回 400；不可访问来源或无效目标返回 404；身份/CSRF 错误为 401/403，账号目录暂不可用为 503。不要从展示名推断身份。

### `GET /api/datasets/{id}/shares`

返回 `{items:[{subject,username}],total}`，现为**转发历史账号**，不是当前权限成员列表。不能依据这里的记录禁用搜索结果或“再次共享”按钮：对方可能已删除副本。来源 ID 已删除时返回 404。

旧 `DELETE /api/datasets/{id}/shares/{subject}` 保留，合法来源访问返回 409，不能撤回对方独立副本。

### `DELETE /api/datasets/{id}`

无请求体，只允许自己的非公共个人集。删除确认对话框应说明不可撤销、只删除自己持有的副本、其他持有者不受影响。

```json
{"success":true,"datasetId":"业务ID","deletedObjects":0,"retainedObjects":0,"pendingObjects":139}
```

200 表示本人的数据集已移除，待回收对象已持久登记。**不是所有物理文件已删完。**后台通常每 5 秒处理一批（最多 32 对象）。空数据集三个计数均为 0。

- `deletedObjects`：当前记录为已物理删除/已不存在的 DICOM 对象数。
- `retainedObjects`：最近检查时仍被其他活跃数据集或进行中的归档任务持有而保留的对象数。
- `pendingObjects`：等待检查/回收或失败重试的对象数。
- 计数按物理对象去重，包含 CT、SEG 等登记对象，不是切片完成度或独占磁盘字节数。以后其他持有者删除/重新上传时计数可以变化，不是永久审计快照。
- 列表、收藏、最近打开及原 ID 的影像、DICOMweb、工作台、标注和统计入口不再允许访问。
- 原所有者重复 DELETE 返回 200，保持幂等；已删除 ID 不会恢复。
- 401 未登录；403 CSRF/公共示例；404 非本人、找不到或不可访问；400 团队集请走团队入口。
- 409 存在有效编辑租约、服务器尚未归档的掩码，或未完成归档任务。提示先关闭工作台，等候保存完成后再删除。不要静默丢弃已接受的编辑。

### `GET /api/datasets/{id}/deletion-status`

无 CSRF，返回同一计数结构。仅该**已删除个人集的原所有者**可读；未删除 ID、他人、公共或团队 ID 返回 404，未登录 401。可由前端手动刷新或有界轮询，停止于 `pendingObjects=0`。无需恢复已经删除的列表项。

### `POST /api/import?datasetId=...`

继续 multipart 字段 `file`，不支持 NIfTI 转换。`.nii` / `.nii.gz`（大小写均匹配）返回 415 和明确中文错误；不会转给 Orthanc。Portal 选中这类文件时在新建数据集前拒绝整个批次，混选 DICOM 与 NIfTI 也会先拒绝；提示改用 DICOM。本次没有增加 NIfTI 接入、ZIP 解包或任意文件存储。

## 存储与并发边界

回收逐个检查 Orthanc **实例 ID**，不会删除整个 Study/Series。引用包括所有未删除的个人、公共、团队数据集的成员关系、仍有效的当前 SEG 发布和未完成快照任务。只要其中任一持有就不物理删除；最后持有者删除时重新登记待回收。文件已不存在（404）按成功处理；暂时失败写入持久队列，服务重启后继续重试。

上传/发布/转发登记与回收沿用 `segmentationStorageGuard=single-process-rw-v1`：共享引用锁持有到真实事务提交，物理删除在独占锁内重新检查。转发与个人删除使用相同转发链锁和数据集行锁。已有 SEG 覆盖清理继续保留，已删除数据集的历史凭据不会永久占用旧 SEG。

该存储保护针对当前单 Java 进程部署。扩成多个 Java 实例前必须替换成跨进程一致的存储协调，不能直接横向复制进程。不要绕过 Java 直接在 Orthanc 管理界面删除仍被业务数据集持有的文件。

删除保留小型身份墓碑、版本凭据、对象 ID 和个人终身操作统计；移除该数据集服务器上的掩码像素内容、旧草稿、租约、归档任务、收藏和最近记录。浏览器 IndexedDB 草稿、已下载文件和部署备份不会被远程追回。旧 ID 的本地草稿不会自动套到重新转发后的新 ID。

## 旧数据迁移与部署

启动时一次性把旧个人共享授权变成接收者各自的快照副本，迁移接收者的收藏/最近以及其自己的兼容草稿，不复制别人的私有草稿；成功后移除旧授权表中的记录。不会调用 Orthanc 复制一遍 CT。已接受但未归档的当前掩码在副本内独立归档，不捏造接收者历史笔画数。

迁移会改变数据库，启用脚本先停网关与本项目 Java，再备份关闭后的 H2、旧 JAR 和 Portal 成品。失败恢复必须同时恢复对应数据库、JAR 和前端，不能只换回旧 JAR。本轮不在生产库创建或删除测试患者数据。

## 验证

后端覆盖独立副本、删除后转回、同文件多持有者、当前 SEG/归档引用保护、权限/CSRF、NIfTI 拒绝、旧授权迁移、清理失败重试及上传与删除锁顺序；另用本地 HTTP 测试服务器检查真实 Orthanc 客户端只请求实例 DELETE 并处理 200/404/503。该 HTTP 替身不代替真实 Orthanc 生产验收。

Portal 已接入删除按钮、二次确认、独立转发说明、历史接收者可再次选择和 NIfTI 提示。桌面/平板/手机的浏览器交互使用合成会话/数据响应验证，不包含真实患者信息。
