# 收藏与最近打开接口（v1）

2026-11-04。健康标记：`GET /api/health` 包含 `homeActivityApi: "v1"`。
此文是已实现接口契约；上线状态须核对实际健康标记。Portal 的真实收藏/最近模块和 OHIF 成功打开回执已接入，并完成本机真实读写联调。界面改动位置与边界见 [前端接入说明](./收藏与最近打开前端接入.md)。

所有请求继续走同源 `8080` 统一入口，以 Cookie 登录。身份取服务端会话中的 `issuer + subject`，不接受前端指定操作者。所有写操作均须使用 `/api/session` 返回的新鲜 CSRF token，并复核账户未切换；参照现有 `request-examples.ts`。GET 不缓存，所有成功响应为 HTTP 200 JSON、`Cache-Control: no-store`。

## 路由

| 方法 | 路径 | 参数/请求体 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/me/favorite-datasets` | `page=0&size=20` | 本人当前可访问的收藏列表 |
| GET | `/api/me/favorite-datasets/state` | 重复查询参数 `datasetId=A&datasetId=B`，1–200 个 | 批量收藏状态 |
| PUT | `/api/me/favorite-datasets/{datasetId}` | 无请求体 | 收藏，幂等，保留首次收藏时间 |
| DELETE | `/api/me/favorite-datasets/{datasetId}` | 无请求体 | 取消收藏，幂等 |
| GET | `/api/me/recent-datasets` | `page=0&size=20` | 最近成功打开的列表及当前 generation |
| GET | `/api/me/recent-datasets/context` | 无 | 工作台进入前取得轻量上报上下文 |
| POST | `/api/me/recent-datasets/{datasetId}` | `{ "eventId": "完整UUID", "generation": "上下文UUID" }` | 记录一次成功打开 |
| DELETE | `/api/me/recent-datasets/{datasetId}` | 无 | 移除本人一条历史，并更新 generation |
| DELETE | `/api/me/recent-datasets` | 无 | 清空本人历史，并更新 generation |

分页仅用于这两个新列表。`page` 从 0 开始，`size` 为 1–100。`total` 是过滤当前权限后、分页前的总数；翻到末页之外时 `items: []`，`total` 仍保留。旧列表接口的结构和 total 语义未修改。

datasetId 是业务数据集 ID，1–100 个字母/数字/下划线/连字符，首字符为字母或数字；不是 StudyInstanceUID、SeriesInstanceUID 或任意 URL。

## 数据格式

列表项包含当前数据集摘要，不需要前端遍历所有团队补名称：

```json
{
  "items": [{
    "dataset": {
      "id": "example-dataset",
      "name": "心脏 CT",
      "access": "shared",
      "scope": "team",
      "ownerUsername": "example-uploader",
      "instanceCount": 60,
      "createdAt": "2026-11-04T00:00:00Z",
      "teamId": "TM-EXAMPLE",
      "teamName": "示例团队"
    },
    "favoritedAt": "2026-11-04T01:00:00Z"
  }],
  "total": 1,
  "page": 0,
  "size": 20
}
```

最近列表将 `favoritedAt` 换成 `lastOpenedAt`，并在顶层增加 `generation`、`retentionDays: 90`、`maxItems: 100`。所有时间由服务器生成，采用 UTC ISO 8601；前端传时间不会影响排序。

- `access`：`owner | shared | public`，说明当前用户与资料的关系，不是标注员/审核员角色。
- `scope`：`personal | team`。`personal` 包括本人、个人共享和公共资料，不等于私密。
- 非团队资料的 `teamId`、`teamName` 为 null。团队资料的 access 仍为 owner/shared，团队来源看 scope。
- 名称、所属团队、实例数按读取时的数据库返回，不保留失权前的旧摘要。
- `instanceCount` 是实例数，不是 CT 掩码完成数或医学完成度。完成度继续使用已有标注统计 API。

其他成功响应：

```ts
// PUT 收藏
{ success: true, datasetId: string, favorited: true, favoritedAt: string }
// DELETE 取消收藏
{ success: true, datasetId: string, favorited: false, favoritedAt: null }
// GET 批量状态：只返回当前可访问项，重复 ID 合并，不可访问/不存在的 ID 均省略
{ items: [{ datasetId: string, favorited: boolean, favoritedAt: string | null }], total: number }
// GET 最近上报上下文
{ generation: string, retentionDays: 90, maxItems: 100, expiresAt: string }
// POST 成功打开：duplicate=true 时返回第一次接受该事件的时间，不更新最近排序
{ success: true, datasetId: string, lastOpenedAt: string, duplicate: boolean }
// DELETE 单条/全部历史：新 generation，用于使在途旧请求失效
{ success: true, generation: string }
```

完整类型见 `home-activity.ts`。

## 收藏的权限与行为

本人、被共享、公共及团队数据集均可收藏，前提是当前有读取权。收藏只保存本人到业务数据集的引用，不复制 CT，不更改共享、团队、标注或 Orthanc 数据。

PUT 重复执行不会增加记录或改变收藏时间；取消后重新收藏会产生新的时间。收藏按时间倒序，同毫秒按数据集 ID 排序。

权限失效、退出团队、团队资料逻辑删除后，列表和批量状态会在计数/分页前过滤，不返回旧名称、团队名等资料。失权后的收藏引用可以通过 DELETE 移除；不存在的本人引用也返回成功，避免通过删除接口探测资源存在性。

## 最近打开由 OHIF 上报

1. 开始一次真实打开流程时，校验会话身份，取得 `/recent-datasets/context`。generation 是账号的历史操作代号，不是登录凭证。
2. 为这次导航生成固定 `eventId = crypto.randomUUID()`，保存此次身份、generation 和数据集上下文。
3. 在工作台已取得授权上下文、目标影像加载到可使用状态后，上报一次 POST。直接链接进入也需要上报。点击首页按钮、展开详情、预取、打开失败均不报。
4. 写入前沿用现有会话复核和 CSRF；切换账号、数据集或退出时取消旧上下文的延迟工作。
5. 同一事件重试必须保持原 eventId 和 generation。正常刷新或重新打开属于新事件，应生成新的 eventId。不要每笔掩码、每次轮询、每次切片切换都上报。

前端上报的是“已打开”的事实；服务器校验登录和当前资料权限，不能检测浏览器是否真的完成了像素渲染。该事件不作为审核通过或标注完成的依据。

同数据集只占一条最近记录。不同事件会更新它的服务器时间和排序；相同事件不会更新排序或恢复已被容量淘汰的条目。同一 eventId 不能用于其他数据集。

首版“继续工作”只恢复到数据集入口；不记录或恢复切片、视角、缩放、患者名、截图或掩码。

## 保留期限与迟到请求

- 用户确认的默认策略：最近 90 天、每人最多 100 个数据集；超出数量时删除最早打开项。收藏不自动过期。
- GET 最近列表和 POST 上报时会清理该账号的过期历史；后台每小时也清理不活跃账号的过期历史。权限失效的引用不对外返回。
- generation 最长有效 24 小时，轻量上下文响应给出 expiresAt；过期时由服务器换代，清理该账号旧的事件去重记录。上下文定时过期不会删除仍在 90 天内的最近数据。
- 删除一条或清空全部历史都会更新账号 generation，阻止旧请求在清理之后把记录补回来。其他资料的在途旧上报也会被拒绝，避免跨标签页迟到写入。
- 旧上下文返回 **409 / `RECENT_CONTEXT_STALE`**。前端应结束这次旧上报，不能换一个新 generation 后自动重发旧事件。下一次用户真正打开资料时，取得新上下文并生成新事件。
- 清理历史只清理本人历史，不删除 CT、SEG、收藏、团队、共享或 IndexedDB 草稿。

可部署配置：`RECENT_RETENTION_DAYS=90`、`RECENT_MAX_ITEMS=100`。一般无需改变。服务端允许期限 1–3650 天、数量 1–1000。

## 错误与联调

| HTTP | 含义 |
| --- | --- |
| 400 | 参数、分页、UUID 或 JSON 不合法；活动参数错误含 `code: INVALID_ACTIVITY_REQUEST` |
| 401 | 未登录或会话身份不属于当前服务器 |
| 403 | CSRF 校验失败；刷新会话后由用户重新确认操作 |
| 404 | 收藏/上报目标不存在或当前无权访问，不区分二者 |
| 409 | `RECENT_CONTEXT_STALE`，或 `EVENT_ID_REUSED`（事件 ID 用于另一资料） |
| 500/503 | 服务异常/不可用；不要用空列表伪装成功 |

新业务错误返回 `{ "error": "说明", "code": "机器码" }`。沿用的登录、CSRF、资源授权和 JSON 解析错误可能只有 error，不能要求所有错误都有 code。

前端接入后至少验证：A/B 隔离、同名账号不同身份、收藏/取消幂等、个人/共享/公共/团队资料、退出团队后的列表与计数、重复打开回执、清空后的迟到请求、换设备/重启持久化、打开失败不产生历史。后端受控测试不等于已验证浏览器端真正成功加载时机。
