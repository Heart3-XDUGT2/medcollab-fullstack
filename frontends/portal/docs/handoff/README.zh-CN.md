## 职责分层

```text
用户浏览器
    |
    +-- Portal：账号入口、数据集列表、导入与共享入口
    |
    +-- OHIF 工作界面：影像加载、标注、保存、重新打开
                |
         统一的业务身份与授权
                |
       Java / Keycloak / 影像存储
```

- Portal：展示后端返回的真实字段，处理本页状态和业务请求，构造受控工作界面入口。
- 后端：认证会话、逐次授权、数据归属、共享、导入及业务持久化，是权限与结果的权威来源。
- OHIF 团队：将业务数据集映射为获授权的 DICOM 源和可恢复标注；不能让 Portal 自行猜 UID 或 Cornerstone 状态。
- 部署负责人：同源代理、回调地址、Cookie、静态资源、SPA 回退及工作界面路径。

## 本轮迁移的行为边界

- 根入口进入数据集首页；保留 `/home`、`/account/sign-in` 和明确标为预览的 `/sign-in`。
- 平台账号入口使用浏览器导航到后端 `/auth/login`、`/auth/register`。密码表单预览不是已接通的真实认证。
- 默认不启用业务 API。示例空间必须主动进入，且不会产生真实云端写入。
- 首页不显示编造的标注进度、最近保存、细权限、标签规范或训练集导出。
- 能在独立 Portal 中启动，不代表 OHIF 或 Java 服务必须同时启动；连接这些服务属于后续联调。
- 原生 OHIF 特有的路径和静态资源不能假装存在于 Portal 内。

## 后续怎样协作修改

1. 从最新主分支建立功能分支，按登录、首页或协议边界提交，避免多人直接覆盖同一文件。
2. 后端接口变更先确认字段、方法、状态和权限语义；在同一次变更中同步 OpenAPI、中文契约、前端适配器及测试数据，不只修改页面文案。
3. 工作界面新增启动参数或回跳能力时，双方更新启动契约；不要临时把业务 ID 拼成 DICOM UID 或开放任意跳转。
4. 提交前执行根 README 中实际存在的检查脚本；PR 说明哪些是模拟协议测试，哪些已经用真实服务验证。
5. 仓库默认私有。新增协作者权限、改为公开或生产发布需要明确决定，迁移和推送不自动授权这些操作。
