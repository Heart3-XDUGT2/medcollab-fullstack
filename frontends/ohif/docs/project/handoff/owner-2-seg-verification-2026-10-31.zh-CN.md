## 本轮执行与结果

1. 使用仓库现有分割 Mode，在共同 CT 上切换单视口。
2. 使用真实画笔拖动，半径 5 mm，创建一个演示分割区域。
3. 从实际标签图像读取体素位置及源 SOP，确认它们属于约定序列。
4. 等待导出需要的源图像进入缓存，调用原生下载命令生成文件。
5. 用 Node 进程中的 dcmjs 读取实际文件并解码 RLE，比较掩膜位置。
6. 完整导航重新启动页面，确认旧标注内存状态已清空。
7. 测试夹具通过 DICOMweb 元数据、实例及帧端点提供刚导出的工件。它在测试进程内实现，不写入公开服务，也不代表真实后端存在。
8. OHIF 通过正常 SEG 导入和激活流程恢复分割，逐一核对标签、源 SOP、体素索引，以及对应源影像的位置、方向与像素间距。
9. 检查绘制与恢复后的局部视口截图；没有更新既有截图基线或放宽阈值。

## 发现的限制

### 源图像必须加载完成

仅看到第一张 CT、甚至已经可以绘制，不代表 120 张源图像全部进入缓存。提前调用原生导出会报 `Referenced source image not in cache ... Ensure the referenced series is fully loaded before storing.`。

本次测试明确通过公开加载 API 等待源图像就绪。后续 `saveDraft` 适配层也应处理加载和进度，不能将此类失败显示为已保存。未修改生产导出代码，也没有通过删除源引用来绕过检查。

### 单帧 SEG 的 SliceThickness 需要继续核实

本次源 CT 的 `SliceThickness` 为 3 mm，导出工件的 Shared Pixel Measures 中为 0。当前切片掩膜的体素与平面位置可以恢复，但还没有证明导出工件独立用于三维重建时能正确解释厚度。这一项作为后续医学数据检查保留，未修补依赖或更改源几何。

STL 计算应基于已确认的完整源网格与分割，不能直接把此工件的 0 当成可信的三维间距。

### 当前验证范围

只覆盖一个轴向 CT 序列、一种默认 SEG 编码、一个标签和一个已绘制切片。没有验证多切片体标注、多个结构、私有标签层、重叠、倾斜方向或标准格式的广泛兼容。RLE 解码使用 dcmjs，并非独立厂商的第三方合规验证。

## 复现

在仓库根目录，先按项目锁文件安装依赖。首次执行需要安装 Playwright Chromium：

```bash
node node_modules/playwright/cli.js install chromium
```

启动开发服务：

```bash
OHIF_OPEN=false pnpm --filter @ohif/app run dev --host 127.0.0.1
```

另一个终端运行：

```bash
node node_modules/@playwright/test/cli.js test --config playwright.owner2.config.ts
```

可通过 `OWNER2_BASE_URL` 指向其他已启动的团队开发环境。测试依赖公开样例可访问；使用软件 WebGL 的无头环境，不进行速度或 GPU 能力评估。

结果默认写入被忽略的 `tests/test-results/`：包含导出的 DICOM、绘制与恢复截图、结构化摘要和失败跟踪。不将运行结果或影像字节加入源码提交。
